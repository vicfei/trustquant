# ADR-0003：逐领域 oracle 与统一 DoD

状态：已接受（M0，2026-11-03）

## 决策

### 1. 每个领域有自己的必要证据（公开验证矩阵的骨架）

| 领域 | 必要证据 | 禁止事项 |
|---|---|---|
| 欧式期权 | QuantLib fixtures、解析公式交叉、put-call parity、边界条件、Greeks 单位检查 | — |
| 组合优化（M1） | 小规模解析可解 QP、原始/对偶可行性、KKT、约束满足、目标值比较；跨求解器对照仅作补充 | 非凸问题上"求解器返回成功"≠全局最优，不得如此宣称 |
| 风险指标（M1，Rust 内置实现） | 手算小样本 fixtures；simple/log 收益、频率年化、价格/总收益、weight/position 口径显式；空数据/单观测/缺失值行为 | — |
| 压力测试（M1） | 可手算的持仓冲击 fixtures、情景定义与基准一致性 | — |
| 数据加载（M1） | Schema/类型/日期序/重复/缺失/编码/恶意 CSV/资源限制用例 | — |
| 清单与重放 | 规范序列化、摘要验证、输入完整性、版本记录、差异报告 | — |
| CLI/MCP/库 | 同一请求的契约一致性与错误语义一致性 | — |

### 2. 统一 DoD 按工具类型适用（不机械套用）
数值工具（定价、优化、风险、压力）：oracle 证据 + 不变量 + 单位语义 + 错误路径 + Eval + 清单/重放 + 文档。
非数值工具（manifest、replay、数据加载的存储部分）：以契约一致性、状态语义（含 unavailable 三态）、并发/原子性、文档为 DoD。

完整矩阵见 `docs/dod-matrix.md`，是 M1 门禁的一部分。

### 3. WASM 定位
**M0–M2 仅作为差分验证目标**（同一核心编译 wasm32 与原生比对，按容差不逐位），不是公开支持的发行接口；是否升格为发行目标由后续 ADR 决定。

### 4. QuantLib 基线（沿用 v1 并重新验收）
Ubuntu 24.04 apt `libquantlib0-dev` 1.33-1（上游 1.33）、g++ 13.3.0 `-O2 -std=c++17`、CI 钉 ubuntu-24.04、`fixtures-regen` 漂移检查。fixture 家族：`date_daycount`（M0 期权链路的日计数依赖）、`black_scholes`（M0 期权 oracle，按类别覆盖：call/put × ITM/OTM/ATM、多期限、多波动率、近零与边界，数量由覆盖类别决定而非机械定值）。

### 5. 第三方 oracle 纪律
FinancePy 等作为独立黑盒 oracle 前：核实许可证（GPL 疑点未排除），仅作 dev/test 期依赖，不随发行包分发，不复制代码。
